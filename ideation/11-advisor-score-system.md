## 1. ✅ GO — 한 줄 정의

> **참모의 두뇌(사고 패턴·편향·전술)는 "악보"라는 텍스트로 표현된다. 유저는 자기 GPT/Gemini에 사양서를 올려 "작곡"한 뒤 게임에 적용한다. 악보 길이(사고 용량)는 참모 레벨(스킬랭크)에 비례한다.**

- 시그니처 삼각 구도(`08`)는 **유지**. 참모(악보=두뇌) × 지휘관(결정) × 손(패링).
- 본 시스템이 채우는 빈칸: `08`에서 모호했던 **"참모가 어떻게 성장하는가"** = *"유저가 악보를 작곡·튜닝한다"*.
- 캐릭터 정체성 "생각 천재·패션 잼병 AI"가 **진짜화** — 참모 두뇌는 유저 폰/외부 AI로 길러지는 실재 AI.

---

## 2. ✅ GO — 레이어 분리 (비용 0 구조의 핵심)

| 레이어 | 역할 | LLM 필요 | 빈도 |
|---|---|---|---|
| **① 참모 두뇌 (전투 중)** | 악보(가중치·제약·룰)로 작전안·위험% 산출 | ❌ **게임 내 규칙 엔진** | 매 턴 |
| **② 악보 작곡 (전투 밖)** | 자연어 목표 → 악보 생성·수정 | ✅ **유저의 외부 AI** (GPT/Gemini 등) | 가끔 |

- **전투 중 LLM 호출 0회** — 빠르고 결정적이고 무료.
- 작곡은 **유저 자기 AI 부담** → 우리 서버 LLM 비용 사실상 0.
- 게임 안 "연주(시뮬레이션)"로 악보 검증 — 이것도 LLM 없이 규칙 엔진.

---

## 3. ✅ GO — 걷기 2축 (Walk-to-Play 철학 통일)

> 걷기 = *"이 세계에서 버틸 수 있는 시간(인내)"*. 전투에서는 **패링 윈도우**, 훈련장에서는 **참모 수련 시간**으로 발현. 하나의 철학.

| 걷기가 주는 것 | 형태 | 충돌? |
|---|---|---|
| **패링 윈도우** (`09` 기존) | 버틸 수 있는 시간 | ✅ 확정 |
| **참모 수련 시간** (본안 새) | 악보 작곡·연습·튜닝 기회(시간·횟수) | ✅ 정합 |
| ~~학습 효율 가속~~ | 같은 수련으로 더 큰 효과 | ❌ 우회 T2W (금지) |

**정합성 검증:**
- 핵심 구분 — **"기회(시간·횟수)는 준다 / 효율(한 번의 효과)은 안 준다"**. `08 §4` "학습가속·토큰회복 금지"는 "효율"에 해당 → 위반 않음.
- **PvE·캠페인 한정**. PvP는 양측 동일 정규화 + 수련 효과 0 반영 (`08` 조건 1·2 정합).
- Walk-to-Play 철학 *"걸은 놈이 강한 건 정당하다(과금 P2W만 차단)"* 과 정합 — 걷기=행동=수련시간은 정당.

## 4. ✅ GO — 세계관 프레임: "참모의 사고 언어"

> 게임 세계 안에서 참모 AI들은 서로 소통·진화하며 만든 **"사고 언어"**. 지휘관(플레이어)은 이 언어를 배워 참모에게 *"어떻게 생각할지"*를 적어준다.

- = **프롬프트 엔지니어링의 게임화** (2025-26 시대정신).
- DSL 명명은 **나중에**(이사님 지시). 본 문서는 직관 이해용 예시 키워드(`SCORE/NEVER/MUST/WEIGHT/TRACK/ON/CONF`)만 사용.

---

## 5. 🟡 설계 — 악보 DSL 세 블록 (예시 — 명명·문법 확정 아님)

> 이사님 기준: *화성학(음악)=너무 쉬움 / 수학=인간에게 너무 어려움 / 프로그래밍=코딩교육 부산물 가능*.
> → **도메인 = 전술 의사결정**(게임 고유, AI 훈련 데이터 부족) / **형식 = 제약 + 가중치 + 트랙**(논리 + 직관 + 다성 구조).

**① 제약(Constraint)** — "절대/반드시" (논리 프로그래밍 맛)
```
NEVER  ally.exposed          # 동료 노출 금지
MUST   hold_point(gate)      # 관문 사수
```

**② 가중치(Bias)** — "얼마나" (슬라이더라 직관, 숫자 직접은 고수만)
```
WEIGHT counterattack 0.85    # 반격 과대인식 (편향)
WEIGHT aggression 0.40
```

**③ 트랙(Track)** — 역할별 층 (다성 음악 구조 차용, 화성학 함정 회피)
```
TRACK attack  { ... }
TRACK defend  { ... }
TRACK read    { ... }        # 적 읽기 전용
```

### 예시 악보 (직관 이해용)
```
SCORE "침착한 분석가" rank-3
  NEVER  ally.exposed
  MUST   hold_point(gate)
  WEIGHT counterattack 0.85
  WEIGHT aggression 0.40

  TRACK read {
    ON enemy.fast    → raise_alert("속도 변화")
    ON enemy.feint   → track_second_blink
  }
  TRACK defend {
    ON alert         → recommend(guard)
    CONF 0.70        # 확신도 (낮으면 칩에 "불확실" 표시)
  }
```

읽으면 인간 직관으로 이해됨. 하지만 **완벽 튜닝**(가중치 균형·트랙 간 충돌·상대 대응)은 숙련도 영역.

---

## 6. 🟡 설계 — AI가 "쉽게 못 푸는" 난이도 4메커니즘

> 설계 원칙: **개별 요소는 직관적이고 쉽되, 요소들 사이의 상호작용·균형·일관성이 어렵다.** AI는 "초안"은 짜주되 "완성"은 인간.

1. **평가 함수가 숨겨짐** — 악보 품질은 게임 내 연주(시뮬레이션) 결과로만. AI가 직접 평가 불가 → 유저 반복 튜닝.
2. **도메인 고유 개념** — "그림자 자갈의 페인트 패턴" 등 게임 내 상황은 외부 AI 훈련 데이터에 부재.
3. **가중치 균형** — 0.85 vs 0.80이 결과 변경. AI는 한 번에 최적값 탐색 곤란.
4. **적대적 환경** — 상대(적/상대 참모)에 맞춰야. 고정 정답 부재.

---

## 7. 🟡 설계 — 악보 길이 × 레벨 곡선 (마비노기 작곡 메타포)

- 참모 레벨 ↑ → 악보 한도("음표" 수) ↑.
- 저레벨: 짧은 악보(단순 편향 몇). 고레벨: 긴 악보(정교한 룰 체계).
- **길다고 무조건 강한 게 아님** — 잘 작곡해야. 고레벨인데 악보 엉망이면 참모 오히려 혼란(편향 과부하 → 위험% 부정확).
- 이것이 *"생각 천재"* 성장의 진짜 의미: **뇌 용량은 커지되 뭘 채우는지는 유저 몫**.
- 세부 수치(음표 수·레벨 구간)는 **본편 조립 시점까지 보류**(`DEVELOPMENT.md` 튜닝 철학 준수).

---

## 8. 🟡 설계 — PvP 정규화 (악보 무게 캡)

- 기존 원칙: PvP 추론/토큰/정보 완전 정규화(`08` 조건 1).
- 본안: PvP는 **"악보 무게 캡"** — 동일 음표 수(예: 100)까지만 악보 적용 허용. 평등.
- 길이 싸움(고레벨 긴 악보)은 **PvE·캠페인**에서 빛남(`08` 조건 2 정합).
- PvP 승패는 여전히 **목표선택 + 패링 실력**. 악보는 작전안 "질"에만 기여.
- 캡 수치·운영은 보류.

---

## 9. ✅ GO — 커뮤니티 / 서브컬처 (마비노기 MML 공유 문화)

- 악보(참모 두뇌) **공유·거래·자랑** — "내 참모 이 악보로 10연승".
- 복붙 → 자기 참모 적용 → 수정. **유저 생성 콘텐츠 = 서버 비용 0 무한 생성**.
- "로봇 대전의 기쁨" 같은 추상적 가치가 구체 악보로 실체화되는 통로.

## 10. 🟡 설계 — 리스크 (미리 식별, 디테일은 본편)

| 리스크 | 대응 방향 |
|---|---|
| **유해 악보** — 텍스트로 부적절 내용 우회 | 입력 검증·샌드박스·악보 색인화 |
| **캡 우회** — 길이 제한 회피 꼼수 | 엄격한 음표(토큰) 카운트 |
| **DSL 밸런스** — 너무 쉬우면 AI가 다 짜고, 너무 어려우면 유저 포기 | **프로토타입 검증 핵심 과제** |

## 11. 🔵 심화 — 코딩교육 / 프롬프트 엔지니어링 교육 (본편 이후)

> 이사님 2026-07-09: *"코딩교육은 심화로 가는 게 좋아보인다."* — 본 설계 흐름에 박지 않음.

- DSL이 조건문(ON)·변수/파라미터(WEIGHT)·논리(NEVER/MUST)·모듈(TRACK)을 내장 → 기초 프로그래밍 개념 자연 습득 부산물.
- "튜토리얼 = 참모에게 생각 가르치기" 포장 → 교육용 에디토리얼 모드 가능.
- "연주(시뮬레이션) 피드백" = 디버깅 교육, "부조화 시각화" = 자기모순 인지 교육.
- 학교/교육용 별도 빌드 = 확장 수익축 후보.
- **단, 이것은 본편 이후 심화. 지금은 DSL 본안이 코딩교육 없이도 성립하도록 설계.**
