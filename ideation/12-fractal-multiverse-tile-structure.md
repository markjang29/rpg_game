## 0. 한 줄 정의

세션(한판) = 세계. 세계는 **작은 타일의 연결**로 '이룸'을 만들고, 그 이룸이 상위 차원에서
**다시 전투의 단위(타일)** 가 된다 — 같은 문법(연결 → 이룸 → 전투)이 모든 스케일에서 반복되는
자기유사(프랙탈) 구조.

## 1. 층위 구조 (프랙탈 레벨)

| 레벨 | 단위 | 하는 일 | 기존 자산 대응 |
|---|---|---|---|
| **L0 타일** | 최소 상호작용 | 이동 1보 · 관찰 1프레임 · 회피(패리) 1회 | 패리·grid_parry(프레임 판정) |
| **L1 세계(한판)** | 타일들의 연결 | 연결이 수렴해 '이룸' 완수(퀘스트·퍼즐·1전투 승리) | 파편전기 1판 · 첫 보스 1턴 인스턴스 |
| **L2 멀티버스** | 세계들의 연결 | 판(세계) 사이를 파편 수집으로 잇는 서사·정치 단위 | 파편전기 서사 프레임('파편'=세계 조각) |
| **L3 재귀** | L2 결과물의 재진입 | 유물·세계 조각이 **상위 판의 타일**로 배치·조합되어 그 자체가 전투 자산(지형·증원·배틀아이템) | — (신규) |

- **자기유사성**: 어느 층위에서든 동일 문법(연결 → 이룸 → 전투)이 반복된다. 규칙 1벌로
  전 층위를 설명할 수 있어야 한다 — 층위마다 새 규칙을 만들면 프랙탈이 아니라 콘텐츠 납품이다.
- **재귀는 L3에서 명시적 종결**: 무한 재귀가 아니라 상한(안: 3~4층)을 두고, 그 안에서만
  "세계 → 타일 → 세계" 사이클이 반복된다.

## 2. 핵심 문법 — 연결 → 이룸 → 전투

1. **연결**: 타일은 붙을 수 있다. 붙는 규칙(정합·대가)은 플레이어가 **관찰·추론으로 발견**한다
   — 규칙을 알려주지 않고 유추 근거만 준다(아하 모먼트 장치).
2. **이룸**: 연결이 임계점을 넘으면 하나의 결과물로 수렴한다(판 하나의 목표).
3. **전투**: 결과물은 그 자체로 다음 스케일의 전투 재료가 된다. 전투도 타일 문법으로 환원된다
   (공격·회피·연계 = 전투 타일의 연결).

## 3. 기존 자산과의 정합 (무복제 · 단일소스 원칙 유지)

- **파편전기**: '파편'이라는 명칭이 이미 세계 조각 의미 — 멀티버스 프레임으로 명칭 그대로 승격 가능.
  새 이름·새 시스템을 만들지 않는다(`web-react/src/apps-main.jsx` PLAYABLE 라벨 그대로).
- **패리 / grid_parry**: L0 타일의 전투 동사. 프레임 판정 구조가 타일 문법의 최소 실증 사례.
- **관찰·추론 모듈(wip)**: 타일 연결 규칙의 '발견'을 담당 — L0→L1 사다리.
- **첫 보스 1턴 인스턴스**(`DRAFT-first-boss-one-turn-instance.md`): L1 세계의 최소 검증판.
- **WLD(월드·배경) 자상**: 세계별 정서 여백 — 걷기 파트의 서사 감정 재료.

## 4. 감정 설계 (사칙 v1 감정 목표 준수 — 미명시 설계 반려)

| 층위 | 감정 목표 | 자극 장치(안) |
|---|---|---|
| L0 | 긴장 → 해방 | 프레임 단위 판정 · 히트스톱 · 숨 틈 |
| L1 | 깨달음 · 성취 | '이룸' 수렴 연출 — 규칙을 내가 발견했다 |
| L2 | 호기심 → 애틋함 | 세계가 연결되는 순간 — "이 세계도 파편이었구나" |
| L3 | 권능감 + 상실 우려 | 내 한판이 카드가 된다 — 상위 전투에서 잃을 수도 있다 |

- L3의 '상실 가능성'은 이 구조의 고유 감정 자산이다 — 세계를 지키는 전투가 되어
  긴장→해방 루프가 서사까지 확장된다.

## 5. 구현 훅 (후보 — 전부 미승인, 설계 1차 보고 대상)

- **Godot 4.7**: L1 세계 = TileMapLayer 씬 1개. 판 결과는 `Resource`로 직렬화 → L3에서
  타일로 재진입. 판 결과 규칙은 `godot-gdscript-headless-testing`으로 단위테스트(CI 게이트).
- **세이브**: 판(세계) 결과 저장(`rpg-genre` save-system)이 곧 멀티버스 연결선 — 세이브 파일
  구조에 '세계 조각' 1급 시민 반영.
- **웹(/apps/rpg)**: 모듈 카드에 `fractal_multiverse`(planned) 등록 후보 — 모듈 API 확장은
  별도 설계 1차 보고 필요(무단 확장 금지).
- **증분 경로**: 신규 엔진·신규 저장소 없이 기존 모듈 재사용(무복제).

## 6. 리스크 · 미결 항목

- **인지부하**: 층위가 많으면 플레이어가 문법을 못 읽는다 — 상한 3~4층 + 층위 전환 연출 필수.
- **콘텐츠량 폭발**: 멀티버스 = 세계 N개 보장 → 절차적 생성(procedural-gen) 필요. 품질 관리
  규칙(정서 일관성 검사)이 선행되어야 한다.
- **가치 척도**: 상위 전투에서 하위 세계 결과물의 강도 환산율 — 밸런스 안 설계 필요.
- **용어**: '멀티버스'는 대외 표현 시 식상할 수 있음 — 내부 명칭은 '파편' 계열 어휘와 통일 검토.
