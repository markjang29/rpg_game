## 모듈식 프로토타입 개발

> 작은 모듈 단위 프로토타입 → 폰 검증 → 모듈 라이브러리 적립 → 본편 조립

각 메커니즘을 독립 실행 가능한 모듈(`demo/modules/<이름>/`)로 먼저 만듭니다. 세부 수치 튜닝은 본편 조립 시점으로 미룹니다 — 지금은 **"작동·느낌 사는가?"** 까지만.

### 모듈 현황

- ✅ **parry** — 패링 손맛 (히트스톱·셰이크·파티클 3축 검증, 2026-07-01)
- ✅ **grid_parry** — 그리드 전술 + 패막 결합
- 🔄 **reasoning × grid_parry 통합** — 참모 보고서 패널 + 전제 토글 + 토큰 3단계 + 패링 (진행 중)
- 🟡 **walk** — 걷기 시스템 (예정)
- 🟡 **color-dye** — 색 염색 시스템 (예정)
- 🟡 **territory** — 영토/지역 시스템 (예정)
- 🟡 **romance** — 로맨스 시스템 (예정)

### 다음 모듈 검증 기준

- 한 턴 의사결정 **20~40초** / 보고서 기본 **3줄 이하** / 터치 **3회 내** 선택·수정·실행
- **"내가 고쳤다"** 는 체감, **"패링으로 위험을 0으로 만들었다"** 는 쾌감 관찰

### PvP "진검승부 + 비김" (설계 중)

- **공정성 최소 조건**: 동일 부대 예산 · 동일 추론 티어 · 동일 토큰 · 동일 정보량 · 보너스 0기여
- **비김의 구조적 원인**: 동시 명령 WEGO 해결 · 목표 기반 점수(코어 파괴 아님) · 턴 제한
- **승패 분리축**: 동일 정보라도 *무엇을 목표로 삼는지* + *패링 실력*이 플레이어 차이
