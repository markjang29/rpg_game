## 0. 왜 "결정 1"의 한 턴인가 — 1턴 선정 근거

시나리오 의뢰서(`SCENARIO-REQUEST-first-boss-reasoning-parry.md`)의 한 판에는 결정이 3개 들어있다 — (1) 맞받 vs 방어, (2) 광역 협동, (3) 처치 vs 봐줌. 그중 **결정 1**을 "핵심 1턴"으로 잡는다.

**이유**: 결정 1만이 시그니처 삼각 구도(`08`) 세 축을 **한 턴 안에 다 터뜨린다.**

| 시그니처 축 | 결정 1에서의 발현 |
|---|---|
| **참모 추론** (편향 보고서) | 공격형 편향 — 위험 0.66× 과소평가. "맞받 추천" |
| **지휘관 결정** (선택/교정) | 심층 분석으로 정정 보고 → 방어 선택 |
| **패막 손맛** (손) | Perfect 패링 → 보스 빈틈 → 바츠 카운터 |

결정 2(광역)는 손맛은 강하지만 추론/결정이 단순하고, 결정 3(처치 vs 봐줌)은 서사이지 전술이 아니다. **한 턴에서 세 축이 모두 발화하는 건 결정 1뿐** — 그래서 이것을 "체감 인스턴스 1턴"으로 콘크리트화한다.

## 1. 1턴의 무대 — 폰 화면에 보이는 것 (show)

> 플레이어가 폰을 켜 **처음 보는 화면**. 세로, 한 손 엄지.

```
┌─────────────────────────┐
│   ◕ ◕ ◕ ◕               │ ← 그림자베어 (눈 4개, 베어울프 체격)
│   [ 그림자베어  ]        │   HP ●●● (3/3)
│   바이러스 감염          │   상태 표시
├─────────────────────────┤
│ [글라스]  [네네]         │ ← 파티 (하단)
│  방패      회복          │
│ [바츠]    [유라]         │
│  근딜      원딜          │
│         ↓                │ ← 글라스 턴 (방어 담당)
├─────────────────────────┤
│  🟦 오드 (참모)          │ ← 참모 칩 (하단 고정)
│  "맞받아치기 추천.       │
│   위험 낮은 편입니다."   │
│  [맞받] [방어] [후퇴]    │ ← 작전안 선택지
│  [🔍 심층 분석 (1)]      │ ← 토큰 버튼
└─────────────────────────┘
```

**한 줄 설정** (이것만 보이면够了):
- **오드(참모)** — "생각은 천재, 패션은 잼병". 전투에선 냉철한 기계 목소리. 지금은 **공격형 편향**.
- **그림자베어** — 원래 숲 수호자. 원기옥 오염(바이러스). 눈이 깜빡이며 공격을 예고.
- **글라스(탱커)** — 묵직한 방패. 걷기를 많이 해서 패링 윈도우가 길다(5.7초).

## 2. 1턴 스토리보드 — 시간순 체감 (★ 본 과제 핵심)

> 플레이어가 겪는 **시간의 흐름** 그대로. Phase A → E. 각 Phase마다 **화면 + 대사 + 숫자 + 선택지**.

### Phase A — 참모 추론 (후보·판단) [0~3초]

화면이 열리면 오드의 칩이 **작전안 3개**를 내놓는다.

```
🟦 오드
"맞받아치기 추천. 위험 낮은 편입니다."
─────────────────────────
[ A. 맞받아치기 ]  ← 오드 강조 표시(★)
   위험 25%   기대 보스 HP -1
[ B. 방어(패링) ]
   위험 12%   카운터 기회
[ C. 후퇴·재정비 ]
   위험 5%    보스 회복 +10%
─────────────────────────
[ 🔍 심층 분석  (토큰 1 남음) ]
```

**플레이어가 찰나에 느끼는 것**: "오드가 A를 밀고 있네. 근데… 위험 25%라고? 이 거대한 곰한테 맞받으라면서 위험이 그게 뭐지? 좀 너무 낮지 않나." → **의심**이 든다.

> **(숫자 메커니즘 — show 안에 숨은 값)**: 표시 위험 25%는 **편향 계수 0.66**이 곱해진 값. 실제(보정 전) 위험은 **38%**. 오드는 공격형이라 킬 기대값을 과대평가하고, 그래서 위험을 0.66배로 줄여 부른다. 플레이어는 이 38%를 아직 모른다.

---

### Phase B — 심층 분석 (편향 정정) ★ 드라마 핵심 [3~6초]

플레이어가 `[🔍 심층 분석]`을 누른다. **한 판에 한 번뿐인 귀중한 토큰**을 소비.

> 화면이 잠깐 어두워지고, 오드의 칩이 **갱신**된다. 기계 같던 목소리에 처음으로 **끊김**이 생긴다.

```
🟦 오드
"…정정합니다."
"보정 전 위험, 제가 낮춰 불렀습니다."

   위험 25% → 38%
   ─────
[ A. 맞받아치기 ]   위험 38%   ← ★ 사라짐
[ B. 방어(패링) ]   위험 12%   ← 사실상 이게 제일 안전
[ C. 후퇴·재정비 ]  위험 5%
```

**플레이어가 느끼는 것 (★체감의 핵)**:

> *"이 참모, 나한테 맞받으라고 하면서 위험을 속였네(본인도 모르게). …민어도 되나?"*

오드는 **거짓말을 한 게 아니다.** 편향일 뿐이다. 하지만 플레이어는 **처음으로 이 참모의 한계를 본다.** 신뢰·의심·교정 — 이 한 텀븀의 침묵이 캐릭터를 만든다.

> **(시나리오팀에 메모)**: 의뢰서 §2 요청대로 — 이 순간의 **"…정정합니다" 앞의 침묵·망설임**을 대사로 살리는 건 시나리오팀 몫이다. 본 draft는 메커니즘 뼈대(25%→38%, 토큰 1)만 제공.

---

### Phase C — 지휘관 결정 (선택지) [6~9초]

정정된 보고를 본 플레이어가 결정한다. **이 순간부터는 참모가 아니라 지휘관(플레이어)의 몫.**

```
결정하세요.
[ A. 맞받아치기 ]  위험 38%   ← 오드 본래 추천. 글라스 피격.
[ B. 방어(패링) ]  위험 12%   ← 정정 후 가장 안전. 카운터 기회.
[ C. 후퇴·재정비 ] 위험 5%    ← 시간은 벌지만 보스 회복.
```

**플레이어 선택: B (방어)** — 오드의 원 추천(A)을 **거르고** 정정된 정보로 간다.

> **(메커니즘)**: 이것이 시그니처 `08`의 "참모≠정답, 지휘관이 고른다"의 발화. 오드가 밀던 A를 플레이어가 교정해 B를 고름. 토큰(심층 분석)이 교정을 가능하게 했고, 교정 없었다면 A를 골렀을 것이다.

선택 직후, 오드가 살짝 반응한다 — **관계 변화의 씨앗**.

```
🟦 오드
"…방어. 알겠습니다. 좋은 판단일 수도."   ← 오드의 추천을 무시한 것에 대한 미세한 반응
```

(오드가 살짝 실망할 수도, 존중할 수도 — 시나리오팀 재량. 어느 쪽이든 **플레이어의 결정이 관계를 흔든다**.)

---

### Phase D — 패막 손맛 (결과) [9~12초]

방어를 고르면 글라스가 보스 공격을 **패링**으로 받아낸다. 여기서 플레이어의 **손**이 들어간다.

**그림자베어 눈 깜빡임 텔** (혼종 + 바이러스):
```
눈:  ◕  .  ◕  .  ◕  .  ◕  .  ●   ← 4번 깜빡 → 마지막에 공격
     (1)    (2)    (3)    (4)   (공격)
     └── 글라스 윈도우 5.7초 (걷기로 벌어들인 시간 자원)
```

- 플레이어는 **4번째 깜빡임**을 읽고, 공격이 날아오는 순간 **엄지로 탭**.
- 타이밍 판정:
  - **Perfect** (±70ms) → 글라스 방패가 빛나며 투사체를 튕김 → **히트스톱 + 진동 + 파티클** (손맛 3축, `parry`/`grid_parry`에서 검증).
  - **Good** (±155ms) → 받아냈지만 충격 → 글라스 HP -1.
  - **Miss** → 글라스 HP -2 (즉사 아님, `10 §6`).

**플레이어의 손맛**: *"4번째 깜빡임이었지… 지금!"* — 터치. Perfect가 터지면 **손끝에서 올라오는 쾌감**.

> **(메커니즘)**: 글라스의 5.7초 윈도우는 **언제 탭을 허용할지의 시간 자원**(`09` Walk-to-Play). Perfect 판정 ±70ms는 윈도우와 무관한 **숙련도 보상**(`08 §2`). 걷기가 Perfect를 만들어주지 않는다 — 그건 플레이어의 손이다.

---

### Phase E — 결정의 파급 (동료 카운터) [12~15초]

**Perfect 패링 성공 시** — 플레이어의 결정(B)과 손맛(Perfect)이 합쳐져 **동료의 활약**이 터진다.

```
🟦 오드
"빈틈 노출. 0.6초."

[바츠]   ← 근딜 바츠가 자동 카운터 (플레이어가 만든 기회)
   💥 보스 HP 3 → 2

네네: "지금!"   ← 힐러의 호응 (파티가 살아있음)
```

**플레이어가 느끼는 것**: *"내가 참모를 교정하고, 손으로 막아내니까 동료가 때려주네. 혼자가 아니야."* — **결정이 서사에 닿는 체감.**

> 오드의 마지막 한마디 (이 턴의 마무리):
> ```
> 🟦 오드
> "…좋은 판단이었습니다. 방어."   ← Phase C의 미세 반응이 여기서 응축
> ```
> (내가 무시했던 참모가, 내 결정이 맞았음을 인정하는 순간 — 관계의 미세한 이동.)

## 3. 1턴 메커니즘 숫자 명세 (show 안에 박힌 값들)

> 과제가 "대사·숫자·선택지로 풀어쓴 스토리보드"이므로, 화면 뒤의 숫자를 한 곳에 모아둔다. **튜닝값이지 결정 아님** — 본편 조립 시점(`DEVELOPMENT.md` 튜닝 철학)까지 보류.

| 항목 | 값 | 출처·일관성 |
|---|---|---|
| 참모 편향 계수 | **0.66×** (위험 과소평가) | 의뢰서 §2 + WIP-second §3.2 일관 |
| 표시 위험 / 실제 위험 (맞받 A) | 25% / **38%** | 0.66×38≈25 |
| 방어(B) 위험 | 12% | 의뢰서 §3 결정1 정합 |
| 후퇴(C) 위험 | 5% / 보스 회복 +10% | draft 산출(조정 가능) |
| 심층 분석 토큰 | 한 판 **1회** | 의뢰서 §2 (귀중한 토큰) |
| 글라스 패링 윈도우 | **5.7초** (걷기 기반 시간 자원) | `10 §3` + 의뢰서 §4 |
| 깜빡임 횟수(이번 턴) | **4회** → 마지막 후 단일 공격 | `10 §5` (3~5 중 고정, 체감 명확화) |
| Perfect 판정 | ±70ms | `08 §2`·`08 §10` (숙련도 보상) |
| Good 판정 | ±155ms | shared/ 재사용 |
| Perfect 보상 | 보스 빈틸 → 바츠 카운터 (HP -1) | 의뢰서 §3 결정1 |

**원칙 정합 체크** (WIP-second §5와 동일 준칙):
- ✅ 걷기(윈도우 5.7초)는 시간 자원일 뿐, Perfect 판정/위험 수치에 0 기여 — `09 §7`·`08 §3` 준수.
- ✅ 참모 정답률 100% 아님 — 편향으로 인해 A(실제 38%)를 추천. 플레이어 교정 가능.
- ✅ 오토배틀러화 차단 — B를 골라도 패링(손) 없이는 카운터가 안 터진다.

## 4. 체감 핵심 — show, don't tell 체크

플레이어가 이 1턴에서 **직접 느끼는 것** (설명이 아니라 체감):

1. **"이 참모가 위험을 낮춰 불렀네"** — 심층 분석 버튼 한 번에 25%→38%로 바뀌는 순간. (Phase B)
2. **"오드 말고 내 판단으로 바꿨다"** — A를 거르고 B를 고르는 1초. 참모≠정답. (Phase C)
3. **"4번째 깜빡임, 지금!"** — 손끝에서 터지는 Perfect. (Phase D)
4. **"내가 만든 틈에 바츠가 때렸다"** — 결정+손이 동료의 활약으로 이어짐. (Phase E)

→ "AI가 정답을 알려주는 게임"이 아니라 **"편향 있는 참모와 심리전하고, 내 손으로 확률을 뒤집는 게임"**이 한 턴 안에 체감된다. 이것이 시그니처 `08`의 1턴 인스턴스다.

## 5. [과제 2] WIP 2건 점검 — 클라이언트(RPG) 관점 메모

### 5.1 `WIP-party-boss-godot-impl-design.md` (4인 파티 보스전 Godot 설계) — 정합 ★높음

이 1턴 인스턴스는 **거의 그대로** 본 WIP의 Phase 4(AI 참모+혼종·상태) 영역에 들어간다.

| 심층 분석 토큰(1회) | — | ⚠ WIP에 **토큰 시스템 누락** (`08 §7`엔 있음) |

| 깜빡임 4회 텔 | §4.1~4.3 (`BLINK_COUNT 3~5`) | ✅ (4는 범위 내) |

| Perfect → 바츠 카운터 | §3 RESOLVE | ⚠ "결정이 동료 카운터를 만드는" 분기가 WIP에 빠짐 |

**클라이언트 메모 (결정 아님, 아침 안건)**:
- WIP-party-boss에 **두 가지가 보완되어야** 이 1턴이 구현된다 — (a) **참모 편향 계수**(`08`엔 있고 의뢰서 핵심인데 WIP엔 누락), (b) **심층 분석 토큰**(한 판 1회 귀중 자원). 둘 다 `reasoning` 모듈쪽 설계를 끌어오면 된다.
- "Perfect 패링 → 동료 카운터" 분기(Phase E)는 WIP §3 상태머신엔 "카운터" 노드가 없다. **이것이 이번 1턴 인스턴스가 WIP에 제안하는 신규 설계 포인트** (아침 결정).

### 5.2 `WIP-second-battle-scene-reasoning-parry.md` (그림자 자객, 2번째 씬) — 관계 = 징검다리

이 1턴 인스턴스(그림자베어)와 WIP-second(그림자 자객)는 **서로 다른 단계**.

| | WIP-second (그림자 자객) | 본 1턴 인스턴스 (그림자베어) |
|---|---|---|
| 단계 | 튜토리얼 다음 **징검다리** | **첫 보스전** (4인 파티) |
| 플레이어 | 단일 | 4인 파티 |
| 핵심 | 패턴 변화 + 편향 정정 체감 | 편향 정정 + 결정 분기 + 동료 카운터 |

**클라이언트 메모 (결정 아님)**:
- WIP-second §3.2 턴1이 **본 인스턴스 Phase A·B의 단일 플레이어 축소판**이다 — 같은 편향(0.66×), 같은 심층 분석 정정 흐름. 즉 **WIP-second가 이 1턴의 "사전 훈련" 역할**을 하도록 정렬되어 있다. ✅
- 단, WIP-second엔 **동료 카운터(Phase E)와 결정 분기(Phase C)가 없다** (단일이라). 이건 의도적 — 2번째 씬이 "참모 편향 정정"만 가르치고, **4인 보스전(본 인스턴스)에서 결정 분기+동료 연계를 가르치는** 난이도 확장 흐름으로 자연스럽다.
- 정합 결론: **WIP-second → 본 1턴 인스턴스로 가는 징검다리가 성립**. 단, 양쪽의 **편향 계수(0.66)와 토큰(심층 분석 1회) 수치를 동일하게 묶어야** 플레이어가 "전에 배운 거네"라고 이어 붙일 수 있다 — 현재 WIP-second §3.2 턴1은 32%→38%로, 본 인스턴스 25%→38%와 미세 불일치. **아침 안건: 튜닝값 통일.**
