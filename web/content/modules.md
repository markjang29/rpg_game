## 모듈식 프로토타입 개발

> 작은 모듈 단위 프로토타입 → 폰 검증 → 모듈 라이브러리 적립 → 본편 조립

각 메커니즘을 독립 실행 가능한 모듈(`demo/modules/<이름>/`)로 먼저 만듭니다. 세부 수치 튜닝은 본편 조립 시점으로 미룹니다 — 지금은 **"작동·느낌 사는가?"** 까지만.

### 모듈 현황

- ✅ **parry** — 패링 손맛 (히트스톱·셰이크·파티클 3축 검증, 2026-07-01)
- ✅ **grid_parry** — 그리드 전술 + 패막 결합
- 🔄 **duel_advance** — 사무라이 진검승부 한 판 (Walk-to-Play). 간보기/버티기 + 공격 결정 + 패링 + 참모 칩 UI (진행 중)
- 🔄 **reasoning × grid_parry 통합** — 참모 보고서 패널 + 전제 토글 + 토큰 3단계 + 패링 (진행 중)
- 🟡 **walk** — 걷기→윈도우 환산 (예정)
- 🟡 **color-dye** — 색 염색 시스템 (예정)
- 🟡 **territory** · **romance** (예정)

### 진검승부 모듈 검증 기준 (`duel_advance`)

- 양측 동일 5.0초 윈도우
- **간보기/버티기**(홀드) + **공격 결정**(탭) + **패링**(탭, ±70ms Perfect/Good/Miss)
- 참모 칩 UI: 상대 "텔" 단서 (≤3줄)
- **심리전 체감**(버티기→상대 선타→역패링) + **패링 역전 쾌감** 관찰

### PvP 정규화 (설계 중)

- **공정성**: 양측 동일 윈도우·동일 추론 티어·동일 토큰·동일 정보량·보너스 0기여
- **승패 분리축**: 동일 정보라도 *무엇을 목표로 삼는지* + *버티기 실력* + *패링 실력*이 플레이어 차이
